# P1.10 — Profiles, settings, caregiver gate

Local profiles, caregiver preferences, and a gate that fast taps cannot open.
This sits on the P1.2 Dexie database and the P1.7 speak screen.

**M0 is not passed.** Nothing here was checked on a device. Do not start from
these notes as evidence that a long press feels right on iOS or Android.

## Caregiver gate

The target is the speak-screen title **صوتي** (`data-testid="caregiver-target"`).
A pointer must stay on that element for **1200 ms** (`CAREGIVER_HOLD_MS` in
`core/access/caregiver-timing.ts`). Releasing earlier, cancelling, or leaving
the title clears the timer. The cell pointer path (`PointerAccessFilter`) is
separate and does not open the gate. There is no click handler on the title.

1200 ms is longer than a tap. The default cell hold is still 0 ms until a
caregiver changes access timing.

The dialog asks for a numeric PIN of **4 to 8 digits**.

- First time (no stored record): the caregiver chooses the PIN and types it
  again. A mismatch stays locked.
- After that: the dialog checks the attempt. A wrong PIN shows
  `الرمز غير صحيح` and stays locked.
- The PIN itself is never stored. The settings row `caregiverPin` is
  `{ salt, hash }`. `salt` is 16 random bytes as lower-case hex. `hash` is
  the SHA-256 hex of the UTF-8 string `` `${salt}:${pin}` `` (WebCrypto via
  `sha256Hex`). Verification hashes the attempt with the stored salt.

While locked, `/settings` and `/profiles` redirect to `/speak`
(`caregiverGateGuard`). The settings link and the **قفل** button are not in
the speak screen until the gate is open. The four spike links and
`data-testid="test-sentence"` stay.

Unlock is a memory signal on `CaregiverGate`. It is not written to
IndexedDB, localStorage, or sessionStorage. A reload starts locked. Hiding
the tab for **60 seconds** (`CAREGIVER_HIDE_LOCK_MS`) locks it again. Coming
back before that cancels the timer. **قفل** locks immediately.

Dexie is loaded with a dynamic import when the PIN is read or written, and
when the speak screen restores saved mode and timing. The speak route does
not statically import the database.

## Profiles

`ProfileDirectory` uses `ProfileRepo`. Each row keeps `id`, `createdAt`,
`updatedAt`, and `name` (`{ ar: '...' }`). Unknown keys are copied through
on update (spread, not a whitelist).

**Gender** is the profile field `gender`, not a settings key. Values are
`m` and `f` (plan §2.9). The settings screen labels them ذكر and أنثى.

The active profile id is the global setting `activeProfileId`. Creating the
first profile selects it. Deleting the active profile selects another one,
or clears the setting when none remain. Delete asks for **تأكيد الحذف** on
the page.

Names in the UI are placeholders only (أحمد، تجربة). No real child data.

## Settings

`AppSettings` writes the global `settings` table through `SettingsRepo.put`,
which snapshots against the active profile (or creates a fictional profile
named تجربة when none exists). Unknown keys on a setting row are kept.

| Key | Value |
|---|---|
| `activeProfileId` | profile id string |
| `gridSize` | `{ rows, cols }` integers from 1 to 12. Preferred size only. It does not change a `BoardDoc`. |
| `speakMode` | `tap` or `sentence`. The speak screen starts in this mode when it is saved and IndexedDB is available. Otherwise it stays `tap`. |
| `accessTiming` | `{ holdMs, debounceMs, activation }` with `activation` of `press` or `release`. |
| `caregiverPin` | `{ salt, hash }` as above. Not edited by the settings form. |

Saving access timing copies it onto `accessTimingLive`, the object
`ACCESS_TIMING` provides. `PointerAccessFilter` reads those fields on each
pointer event. Defaults stay `holdMs: 0`, `debounceMs: 0`,
`activation: 'release'` until a caregiver saves something else.

Routes, both lazy, both behind the guard, both before the `**` redirect:
`/settings`, `/profiles`. `base href` is still `/`.

## Device note

Not run on a phone. Port 4200 was left alone. On a device, check that a
long press on صوتي opens the PIN dialog, that a quick tap does not, and
that iOS does not keep a text-selection callout on the title (`user-select:
none` and `contextmenu` are prevented, which is not a substitute for a
device check).
