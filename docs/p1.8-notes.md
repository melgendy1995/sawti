# P1.8 — AudioService

Speak-on-tap and the sentence button now go through `AudioService`. The P0.4 spike board is unchanged. Pack art, pack audio, and caregiver recordings are still later tasks, so the default resolvers return null and the device speaks with Web Speech when an Arabic voice exists.

**M0 is not passed.** p95 ≤ 150 ms on a D2 phone is a human measurement. This change does not certify it. See `docs/p1.8-device-checklist.md`.

## Chain

`AudioService.speak` looks only at buffers decoded when the board opened:

1. Caregiver recording for that cell (`RECORDING_RESOLVER`)
2. Pack clip for `vocabKey` + gender + voice (`PACK_CLIP_RESOLVER`, `CLIP_IDENTITY`)
3. Device TTS, best Arabic voice: `ar-EG`, then `ar-SA`, then any other `ar` / `ar-*`
4. Large text and the banner `لا يوجد صوت`

`speak` does not call the resolvers and does not `fetch`. `prefetch` (the speak screen runs it when the board opens) may fetch a URL or decode bytes. A buffer already on the clip wins over bytes and over a URL.

If a cached buffer will not start, the next source is tried. Nothing in this chain returns without either starting audio or setting the banner.

There is no offline neural / Piper engine and no new Capacitor plugin. Inside the Android WebView the TTS adapter is still Web Speech. `NativeTtsAdapter` is only an interface.

## How to inject a fake

Tokens are `providedIn: 'root'`. Override them in `TestBed` or a later app provider:

| Token | Default |
|---|---|
| `RECORDING_RESOLVER` | `resolve` returns null |
| `PACK_CLIP_RESOLVER` | `resolve` returns null |
| `CLIP_IDENTITY` | `{ gender: 'f', voice: 'default' }` until P1.10 |
| `CLIP_DECODER` | `WebClipDecoder` (shared `AudioEngine`, `audioSession.type = 'playback'`) |
| `TTS_ADAPTER` | `WebSpeechTtsAdapter` |
| `SPEECH_SYNTHESIS` | global `speechSynthesis`, or null |
| `CELL_SPEAKER` | `AudioCellSpeaker` |

`MemoryCellSpeaker` is still `providedIn: 'root'`. Speak behavior tests pass `{ provide: CELL_SPEAKER, useExisting: MemoryCellSpeaker }`.

`AudioCellSpeaker` reads `vocabKey` from the open board and calls `AudioService`. Spoken text stays `cell.spoken` when that string is non-blank, otherwise the label (P1.7).

## What you see

`/speak` prefetches the open board. If nothing can play, `data-testid="no-voice-banner"` says `لا يوجد صوت` and `data-testid="spoken-fallback"` shows the words in a large line. The Egyptian test sentence and the footer links are unchanged.

`/audio/diagnostics` adds a `data-testid="chain-status"` block: TTS available, the chosen Arabic voice, the last source (`recording`, `pack`, `tts`, `text`), the voice count, and the audio session type. The 30-tap meter is unchanged.

## What this does not do

- P1.5 pack images, P1.6 pack clips, P1.9 caregiver recordings. Ports only.
- P1.10 caregiver gate and the real gender/voice setting. `CLIP_IDENTITY` is a placeholder.
- Piper / offline neural TTS (phase 3 spike).
- A native TTS plugin. Do not add one for this task.
- Certifying tap-to-start p95. That is the device checklist.
