# P1.12 — UpdateService

The app shell uses the `SwUpdate` that `app.config.ts` already provides.
`VersionCheck` reads `/version.json` for the APK notice. Neither path reloads
the speak screen on its own.

## Reload rules

`isSpeakUrl` treats `''`, `'/'`, and `'/speak'` as the speak screen. Query and
hash are ignored.

- A `VERSION_READY` event after startup never calls `activateUpdate()` or the
  reload token. `UpdateService.updateAvailable` becomes true. Caregiver mode
  (P1.10) calls `applyNow()`. There is no "Update now" control on the speak
  screen in this change.
- `checkOnLaunch()` runs from `provideSawtiUpdates()` (`provideAppInitializer`).
  If `checkForUpdate()` reports a version that is already waiting, and the
  current URL is not the speak screen, that waiting update is activated and
  the page reloads once. That is the next-launch apply (a refresh of `/voice`,
  for example).
- The same launch check does **not** reload when the URL is already the speak
  screen, including the `''` → `speak` redirect. The default open of the app
  lands there, so a waiting shell update waits for `applyNow()` instead of
  refreshing under a sentence. A launch reload on `/speak` was rejected
  because the acceptance rule is that the speak screen never reloads by itself.
- `applyNow()` does activate and reload, including on `/speak`. It is the
  explicit caregiver action, not a surprise.
- Reload goes through the `APP_RELOAD` token (`location.reload` by default).

## Unrecoverable service worker

`SwUpdate.unrecoverable` is not ignored and does not reload by itself. A
full-screen Arabic notice (`#sawti-update-notice`) says:

> تعذّر تشغيل هذه النسخة من التطبيق. أعد التحميل عندما لا يتكلم أحد.

The button **إعادة التحميل** calls `reloadAfterUnrecoverable()`. The caregiver
chooses the moment, so a broken shell does not cut off a word. The notice is
built with `textContent` (no HTML from the worker reason).

## version.json

`VERSION_JSON_URL` defaults to the relative path `/version.json`.
`APP_VERSION_CODE` defaults to `1`. Tests replace both tokens. No Capacitor
plugin and no production domain are added.

The check uses `fetch` with `cache: 'no-store'`. A missing file, a non-OK
response, invalid JSON, or a network error returns `status: 'unavailable'`
and does not throw. Those failures do not write the daily stamp, so the next
launch can try again.

A successful parse stores `sawti.versionJsonCheckedAt` through `VERSION_STAMP_STORE`, which reads and writes `localStorage`. A private-mode throw is ignored. Tests supply a memory store because this Node runner does not provide `localStorage`.
Another `check()` inside 24 hours returns `status: 'skipped'` and does not
fetch. It also leaves a previous block in place.

Flat document (this is what `app/public/version.json` ships as a placeholder):

| Field | Role |
|---|---|
| `latestVersion` | Display name. Plan v1.0 called this `android.latestVersionName` / `web.latestVersion`. |
| `latestVersionCode` | Newer than `APP_VERSION_CODE` sets `updateAvailable` (no block). |
| `minSupportedVersionCode` | Greater than `APP_VERSION_CODE` blocks. Equal does not. Security or data bugs only, when a human publishes the file. |
| `apkUrl` | GitHub Releases page (ADR-12). The block notice links it only when it is `https:`. |
| `certSha256` | Signing cert. Plan v1.0 named this `signingCertSha256`. Carried, not checked here. |
| `releasedAt` | Optional. |

`parseVersionDocument` also accepts the nested plan shape: `android.latestVersionCode`, `android.latestVersionName`, `android.minSupportedVersionCode`, `android.apkUrl`, `android.signingCertSha256`, and `web.latestVersion`. Top-level `latestVersionCode` wins when it is a finite number.

When an update is required the same notice host shows:

> يلزم تحديث التطبيق. هذا الإصدار لم يعد مدعوماً لأسباب أمان أو بيانات.

The action is **فتح صفحة الإصدار**. It does not reload the app and it does not install an APK.

The placeholder `certSha256` is zeros. `apkUrl` is `https://github.com/melgendy1995/sawti/releases`. `ngsw-config.json` is unchanged, so `/packs/**` and spike clips are not precached, and `version.json` is not in the app-shell group.
