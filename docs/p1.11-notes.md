# P1.11 — Backup and restore `.sawti`

A caregiver can export the local database to a `.sawti` file and import it again.
The file is a zip. A passphrase is optional. The passphrase checkbox starts
unticked. The passphrase is never written to Dexie, the media store, or the file.

This was not checked on a device. Do not treat these notes as a pass of M0.

## Crypto parameters for Mahmoud's review

These are the parameters the code uses. They are a proposal. OWASP's Password
Storage Cheat Sheet, fetched 2026-11-05 from
`https://github.com/OWASP/CheatSheetSeries/blob/master/cheatsheets/Password_Storage_Cheat_Sheet.md`,
still lists **PBKDF2-HMAC-SHA256: 600,000 iterations** (the cheat sheet dates
that work-factor table to December 2022 RTX 4000 testing). OWASP also says to
prefer Argon2id when FIPS-140 is not required. This task stays on PBKDF2
because that is the plan. Please confirm 600,000 is still the iteration count
you want before a release.

| Parameter | Value |
|---|---|
| Outer format | `sawti-enc-1` |
| KDF | PBKDF2, hash SHA-256 (`PBKDF2-SHA256`) |
| Iterations | **600000** exactly. Decrypt rejects any other count. |
| Salt | 16 random bytes (`crypto.getRandomValues`), standard base64 in `envelope.json` |
| Derived key | 256 bits, AES-GCM, non-extractable |
| Cipher | AES-256-GCM, WebCrypto default 128-bit tag. No custom `tagLength`. |
| Chunk size | 4194304 bytes (4 MiB) |
| Per-chunk IV | 12 random bytes. A new IV for every chunk. Not a counter. |
| AAD | 5 bytes: uint32 big-endian `chunkIndex` (from 0), then uint8 `isLast` (1 or 0) |
| What is encrypted | The entire plain zip (profiles, boards, settings, media) |
| What is not encrypted | `envelope.json` (`format`, `kdf`, `iterations`, `salt`, `chunkSize`) |

No pepper, no extra HMAC, no compression before encryption, and no second KDF.

### Framing that is not in the plan text

`payload.bin` has to mark where each chunk ends. Each frame is:

`uint32be ciphertextByteLength | 12-byte IV | ciphertext||tag`

`ciphertextByteLength` includes the 16-byte GCM tag and excludes the IV and the
length field. An empty plain zip is one last frame of empty plaintext, still
authenticated. A length that runs past the buffer is a corrupt file. A frame
that fails AES-GCM authentication is reported as a wrong passphrase.

Decrypt accepts only `iterations === 600000` and `chunkSize === 4194304`.
Unknown extra JSON fields on the envelope are ignored. A wrong `format` or
`kdf` is corrupt.

## Plain archive

| Member | Contents |
|---|---|
| `manifest.json` | `schemaVersion` 1, `appVersion`, `createdAt`, `profileIds`, `encrypted: false` |
| `profiles/<id>.json` | Full Dexie profile row, unknown keys included |
| `boards/<id>.json` | Full Dexie board row (`doc` included), unknown keys included |
| `settings.json` | Array of settings rows. Extra member so settings restore. |
| `media/<sha256>.<ext>` | Raw bytes. This version writes extension `bin`. The hash of the bytes must match the filename. |

`schemaVersion` here is the **backup** format, not the board document's
`schemaVersion`. A backup `schemaVersion` greater than 1 is rejected with
`حدّث التطبيق` / `Update the app`. Nothing is written.

Ids in paths are limited to letters, digits, `_`, and `-`.

## Encrypted archive

A zip with only `envelope.json` and `payload.bin`. `payload.bin` is the plain
zip above. The inner manifest still says `encrypted: false`. The UI treats the
file as encrypted when `envelope.json` is present.

## Import

1. Unzip the outer file. `envelope.json` means encrypted. `manifest.json` means plain. Anything else is corrupt.
2. Encrypted files ask for the passphrase before preview. A wrong passphrase throws a clear Arabic and English error and does not touch Dexie or the media store.
3. Unpack and check the backup schema. A future schema, a corrupt zip, or a truncated payload stops here. The database is unchanged, including snapshots.
4. Show a preview: profile names, board count, media count, and whether a passphrase was used.
5. On confirm, write media bytes, then one `mutateProfile` transaction snapshots existing profiles (last 10, same helper as P1.2) and replaces profiles, boards, and settings. The media index is replaced after that transaction commits.

Cancelled imports and failed decrypts do not take a snapshot.

## Share warning and reminder

The download anchor is created only after the caregiver presses the acknowledge
button. The warning is shown in Arabic and English. Cancelling does not
download and does not set `lastSuccessfulBackupAt`.

`lastSuccessfulBackupAt` is a global settings value (ISO-8601). The backup page
and the settings page show a reminder when it is missing or 7 days old or
older. The clock is `BACKUP_NOW` so tests can pin the time. The speak screen
does not link to backup. `/backup` uses `caregiverGateGuard`, the same guard
as settings and profiles.

Export uses `Blob` and `<a download="sawti-YYYY-MM-DD.sawti">`. No new
Capacitor plugin.

## Not in this task

iOS home-screen icon deletion (P1.13) is not implemented. The weekly reminder
is the only nudge. Onboarding copy about deleting the icon is still later.

Pack bytes are not included unless they already have a media-index row. Restored
blobs are stored in the `media` namespace. The media index `createdAt` is the
import time, not the original row. Profile rows, board rows, settings rows, and
media hashes are what the round trip checks.
