# P0.4 device checklist

Run this on a phone. The Mac serves the app. Stop the server when you finish (Ctrl+C). Do not leave it running.

JavaScript p95 is the in-app meter (`pointerup` → `AudioBufferSourceNode.start()`). Ear latency is a separate phone-camera check. This page does not measure the ear. D1 and a budget Android are your job.

Paste results into `docs/adr/ADR-p0.4-iphone-silent-switch.md`, section **Device results**.

## Serve

1. على الماك، من الطرفية:

   On the Mac, in a terminal:

   ```
   cd /Users/mahmoudelgendy/Documents/Files/projects/sawti/app
   npx ng serve --host 0.0.0.0 --port 4200
   ```

2. عنوان الماك على الشبكة (يتغيّر). مثال سابق على هذه الشبكة: `192.168.1.20`.

   LAN IP (it can change). An earlier address on this network was `192.168.1.20`.

   ```
   ipconfig getifaddr en0
   ```

3. من الهاتف، نفس الواي فاي، افتح:

   On the phone, same Wi-Fi, open:

   `http://<LAN-IP>:4200/audio`

   مثال / example: `http://192.168.1.20:4200/audio`

4. لميزات تريد HTTPS (عامل الخدمة، وتثبيت PWA لاحقاً):

   For features that want HTTPS (service worker, and later PWA install):

   ```
   npx ng serve --host 0.0.0.0 --port 4200 --ssl
   ```

   ثم افتح `https://<LAN-IP>:4200/audio` واقبل تحذير الشهادة الذاتية.

   Then open `https://<LAN-IP>:4200/audio` and accept the self-signed warning.

5. Tailscale غير مثبّت هنا. إن ثبّته لاحقاً، العنوان يكون ناتج `tailscale ip -4`. ليس مطلوباً لهذه التجربة.

   Tailscale is not installed. If you install it later, the address is the output of `tailscale ip -4`. Not required for this spike.

6. عند الانتهاء: Ctrl+C في طرفية `ng serve`. لا تترك الخادم شغّالاً.

   When finished: Ctrl+C in the `ng serve` terminal. Do not leave the server running.

`/storage` من صفحة الكلام يرجع إلى الكلام حتى P0.6. هذا متوقّع.

`/storage` from the speak page redirects back to speak until P0.6. That is expected.

المقاطع نغمات قصيرة وليست كلاماً. إن فشل مقطع يظهر نص الزر وتحذير «لا يوجد صوت».

The clips are short tones, not speech. A failed clip still shows the cell label and a "no voice" warning.

## Steps

1. أول لمس يفتح الصوت. اضغط عدة خلايا واستمع (ماء، أكل، مدرسة، …).

   The first tap unlocks audio. Tap several cells and listen (ماء، أكل، مدرسة، …).

2. إن لم تسمع شيئاً اختر «لا أسمع شيئاً». يجب أن يظهر تحذير كبير. الصمت بلا تحذير عطل Sev-0.

   If you hear nothing, choose "I hear nothing". A large warning must show. Silence with no warning is Sev-0.

3. افتح «تشخيص الصوت» (`/audio/diagnostics`). بعد انتهاء «يجري تجهيز المقطع» اضغط زر القياس 30 مرة. انسخ التقرير.

   Open diagnostics (`/audio/diagnostics`). After decoding finishes, tap the measure button 30 times. Copy the report.

4. سجّل p50 و p95 والحكم مقابل 150 ms. هذا رقم جافاسكريبت وليس زمن الأذن.

   Record p50, p95, and the pass/fail against 150 ms. That number is JavaScript time, not ear latency.

5. آيفون: مفتاح الصامت **تشغيل**. هل ما زال الصوت يخرج؟ إن لم يخرج، هل التحذير ظاهر؟ ثم أوقف الصامت وتأكد أن الصوت رجع.

   iPhone: silent switch **on**. Does audio still play? If not, is the on-screen warning visible? Then switch it **off** and confirm audio.

6. أرسل الصفحة للخلفية أو اقفل الهاتف ثم ارجع. اضغط خلية. يجب أن يعمل الصوت بعد الرجوع، أو يظهر تحذير.

   Background the page or lock the phone, then return. Tap a cell. Audio should work after resume, or a warning should show.

7. اختياري لاحقاً، غير مطلوب الآن: افصل بلوتوث (الخطة §5.10). التطبيق يعيد `resume` عند إظهار الصفحة فقط، بلا مستمع عتاد للبلوتوث.

   Optional later, not required now: disconnect Bluetooth (plan §5.10). The app only calls `resume` when the page is shown again. There is no Bluetooth hardware hook.

8. الصق التقرير ونتائج الجدول في `docs/adr/ADR-p0.4-iphone-silent-switch.md` تحت **Device results**.

   Paste the report and the table into `docs/adr/ADR-p0.4-iphone-silent-switch.md` under **Device results**.
