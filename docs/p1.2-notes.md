# P1.2 — Dexie data layer, repositories, MediaStore, snapshots

Structured data for Sawti lives in Dexie (`SawtiDb`, database name `sawti`).
Blobs live behind `AppMediaStore`. This depends on the P1.1 board domain and
the P0.6 media backends.

**M0 is not passed.** The 14-day iOS storage soak is still a human go/no-go.
Web media stays **IndexedDB first, OPFS if that self-test fails**. Nothing in
this layer assumes either backend won. Device results stay in
`docs/adr/ADR-02-mediastore-ios-blobs.md` and `docs/p0.6-device-checklist.md`.

## Public API

Dexie is only imported from `app/src/app/core/storage/` (enforced in
`app/eslint.config.js`). Features talk to repositories. `@capacitor/*` stays
in `app/src/app/core/platform/`. Domain code stays free of Angular, Dexie, and
Capacitor.

| Piece | Path | Role |
|---|---|---|
| `SawtiDb` | `core/storage/sawti-db.ts` | `version(1)` tables: profiles, boards, media, packs, packItems, snapshots, settings. Optional constructor name defaults to `sawti`. |
| `liveSignal` | `core/storage/live.ts` | `toSignal(from(liveQuery(...)))`. Not imported by speak or the app shell. |
| `ProfileRepo`, `BoardRepo`, `PackRepo`, `SettingsRepo`, `MediaRepo` | `core/storage/repos/` | The only writers. `OutboxRepo` is P4 and is not implemented. |
| `snapshotProfile`, `pruneSnapshots` | `core/storage/snapshot.ts` | Explicit snapshot APIs. |
| `mutateProfile` | `core/storage/write.ts` | One `db.transaction('rw', ...)` around the snapshot, the write, and the prune. |
| `loadV1Fixture` | `core/storage/fixture-db.ts` | Loads `content/fixtures/db/v1.0/sawti.json`. |
| `storageStatus` | `core/storage/storage-status.ts` | Quota, persisted flag, last snapshot time, media byte count, deletion warning. No settings page. |
| `AppMediaStore`, `wrapBlobStore` | `core/storage/app-media-store.ts` | `put` → sha256, `getUrl`, `getArrayBuffer`, `delete`, `usage`. |
| `selectWebMediaStore` | `core/storage/select-web-media.ts` | IDB then OPFS. |
| `NativeMediaStore`, `nativeAppMediaStore` | `core/platform/` | Capacitor Filesystem. |

`version(1)` does **not** create `outbox`, `conflicts` (P4), or `usage` (P5).
The class still declares those tables so a later version can add them.
`// version(2) adds outbox, conflicts (P4); version(3) adds usage (P5)`.

Caregiver writes (profile, board, settings) go through `mutateProfile`. The
transaction body snapshots first, runs the write, then prunes. The line
`// P4: dirty records {recordId, kind, baseRev}` is where a later outbox upsert
joins that same transaction. Pack and media index writes do not snapshot.
`BoardRepo.save` stores the `BoardDoc` object it was given. It does not move
cells. `BoardRepo.applyBuiltOp` is the only repository method that calls a
domain op (`applyOpResult`); the domain decides positions (INV-1).

`MediaRepo` is a thin index: `{ sha256, bytes, createdAt, backend, namespace }`.
Blob bytes are not stored in Dexie. `AppMediaStore.put` writes the blob once,
under `mediaKey(sha256, namespace)` which is `${namespace}__${sha256}`
(`media` or `packs`). That flat key is what OPFS can store (it rejects
slashes). Zip extract and zip hashing are P1.6.

Unknown top-level keys on profiles, settings, pack rows, and the media index
are written with object spread, not a field whitelist. Unknown keys on a
board and on its cells live inside `doc` and are stored with that object.

## Snapshots

`snapshotProfile(db, profileId)` stores the profile row (or null), that
profile's boards, and **all** settings (settings are global; the snapshot is
still keyed by `profileId`). `pruneSnapshots(db, profileId, keep = 10)` sorts
that profile's rows by `createdAt` then `id`, oldest first, and deletes until
10 remain. Other profiles are left alone.

`mutateProfile` snapshots and then prunes, so a caregiver save never leaves
more than 10 snapshots for that profile. A thrown write rolls the new snapshot
back with the transaction.

Every `version(n).upgrade` must call `snapshotBeforeUpgrade` **before** it
changes rows. `version(1)` runs that hook when the database is created (tables
are empty, so it does nothing). Upgrade snapshots are not pruned in the same
hook.

## Web backend selection

`selectWebMediaStore()`:

1. `new IndexedDbMediaStore('sawti-media-idb')` when IndexedDB exists.
2. `selfTest` with an 8-byte probe. The probe key is deleted by `selfTest`.
3. If that matches, that store is wrapped as `AppMediaStore`.
4. Otherwise `new OpfsMediaStore('sawti-media-opfs')` and the same self-test.
5. If neither passes, it throws `No web media backend passed the self-test (IDB then OPFS).`

The P0.6 soak classes are unchanged when constructed with no arguments: they
still use `sawti-soak-idb` and `sawti-soak-opfs`. The app uses different names
so a soak `clear()` does not delete user media. `getUrl` on the web wrapper
returns `URL.createObjectURL`; the caller may revoke it.

There is no separate device checklist for P1.2. The `/storage` soak page is
unchanged aside from a type that keeps the soak map on `'idb' | 'opfs'` after
`MediaBackend` gained `'native'`.

## NativeMediaStore

`app/src/app/core/platform/native-media-store.ts` implements the P0.6
`MediaStore` with `backend: 'native'`. Files go under `Directory.Data` /
`sawti-media/`, written as base64 with no `encoding` so the plugin stores
bytes. `urlFor` uses `Filesystem.getUri` and `Capacitor.convertFileSrc`.
`nativeAppMediaStore()` is the `AppMediaStore` over that class. Tests inject
a fake filesystem; they do not run `npx cap run`.

## Loading the v1.0 fixture

`content/fixtures/db/v1.0/sawti.json` is a JSON export of the version(1)
tables: one example profile, the P1.1 example board (plus `futureField` on the
board and `futureCellField` on the water cell), and a `locale` setting with
`futureSetting`. Media, packs, and snapshots are empty.

```ts
import 'fake-indexeddb/auto'; // tests only
import { readFileSync } from 'node:fs';
import { loadV1Fixture, type V1Fixture } from './fixture-db';
import { SawtiDb } from './sawti-db';

const fixture = JSON.parse(readFileSync('content/fixtures/db/v1.0/sawti.json', 'utf8')) as V1Fixture;
const db = new SawtiDb();
await loadV1Fixture(db, fixture);
```

`npm test` from `app/` covers this with `fake-indexeddb`. A green run does
**not** mean the 14-day soak passed.
